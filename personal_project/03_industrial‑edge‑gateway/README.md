# 工业物联网边缘网关（MCU + Linux双芯片架构）
## 项目简介
传统纯MCU网关算力有限，很难实现本地数据库存储、网页可视化、复杂数据预处理。本项目采用**RK3568 Linux边缘网关 + ESP32‑S3采集终端**双芯片架构搭建端‑边‑云物联网原型。
ESP32‑S3作为现场终端完成传感器采集，通过Wi‑Fi上报数据；RK3568承担边缘计算能力，部署本地MQTT Broker，使用SQLite实现断网本地缓存，网络恢复自动补发历史数据；配套Web看板可视化设备状态，解决工业弱网环境下数据丢失的痛点。

## 系统架构
1. **终端采集层 ESP32‑S3（FreeRTOS）**
传感器采集任务、MQTT网络任务、指令解析任务；NVS持久化网络配置；上报传感器数据，接收网关下发控制指令。
2. **边缘网关层 RK3568（Linux）**
- Mosquitto MQTT Broker：接收多台ESP32终端的MQTT连接与消息转发
- 业务服务程序：订阅设备上报主题，JSON解析；SQLite做时序数据持久化；断线缓存+网络恢复补发逻辑；TCP‑Socket服务备选通信链路
- Web服务：读取数据库数据，Web看板展示实时、历史传感器数据
3. 扩展：RK3568可对接公有云，实现完整端‑边‑云链路。

## 技术栈
RK3568 Linux、ESP32‑S3、FreeRTOS、MQTT、TCP Socket、SQLite3、cJSON、Wi‑Fi

## 核心功能
1. ESP32终端：周期性采集传感器数据，MQTT上报；支持断线指数退避重连；接收网关下发控制指令执行动作。
2. RK3568边缘网关
- 本地MQTT Broker，支持多台ESP32终端同时接入，Topic隔离设备消息
- SQLite本地持久化缓存：网络断开数据落盘；网络恢复按时间顺序自动补发缓存数据，防止工业弱网丢数
- TCP‑Socket备用通信通道，处理大报文控制指令；自定义帧头+长度+CRC处理粘包
- Web看板展示实时数据，可查看历史时序记录
3. 完成端‑边联调，打通采集‑传输‑存储‑可视化完整业务闭环。

## 关键难点与解决方案
1. **工业Wi‑Fi网络波动，断网数据丢失**
内存队列断电会丢失数据；收到设备上报消息优先写入SQLite磁盘数据库；网络恢复按时间顺序逐条补发，保证数据不丢失。同时设置缓存最大条数，防止数据库无限膨胀。

2. **TCP Socket通信粘包问题**
TCP是字节流没有帧边界；自定义帧头+报文长度+CRC校验，按完整帧解析报文，不依赖JSON分隔。

3. **SQLite多线程并发写数据库报错database‑locked**
MQTT回调线程、Socket业务线程同时操作数据库；数据库写操作加互斥锁，保证同一时刻只有一处执行写事务，开启WAL预写日志模式优化并发。

4. **MQTT重连后丢失离线消息**
终端开启CleanSession=0持久会话；网关侧依靠SQLite磁盘兜底，不完全依赖MQTT会话缓存。

## 测试验证结果
- 多台ESP32终端同时接入网关，消息收发正常；
- 人为断开Wi‑Fi模拟弱网断网，采集数据全部落盘；恢复网络，历史缓存自动补发；
- Web看板实时渲染传感器数据，端‑边‑云全链路可运行；长时间连续运行稳定。
