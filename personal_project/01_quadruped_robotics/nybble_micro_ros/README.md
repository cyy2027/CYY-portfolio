# ROS 2 + micro-ROS 四足异构控制（nybble_micro_ros）

> 🚧 **状态：仅有架构设计** ｜ 无实机 ｜ 无自有代码 ｜ 无实测数据
>
> 目标平台：猫形小型四足（12 自由度舵机关节，Nybble 类）。
> 本目录公开的是 **设计文档**（[design.md](./design.md)），不是可运行工程。

## 一、这套方案要解决什么

`hyperdog_rtos_control` 那套把规划全部压在主控 MCU 上：确定性强、成本低，但步态算法一改就要重新
烧固件，且受主频与 RAM 限制，逆运动学矩阵运算与姿态补偿很难做复杂。

这套方案的取舍是**把规划层搬到 Linux 上位机**，MCU 只做实时执行：

```text
Ubuntu + ROS 2 Foxy            micro-ROS Agent (XRCE-DDS)         STM32 + FreeRTOS
┌───────────────────┐         ┌──────────────────────┐          ┌──────────────────┐
│ IK 解算            │  Topic  │ 序列化 / 反序列化      │ UART+DMA │ ros_msg_recv_task │
│ Trot 步态轨迹生成   │ ──────► │ 会话与重传            │ ───────► │ motor_ctrl_task   │
│ 机身姿态补偿        │ ◄────── │                      │ ◄─────── │ state_report_task │
└───────────────────┘         └──────────────────────┘          └──────────────────┘
                                                                          │ TIM1/TIM8 PWM
                                                                      12 路关节
```

好处是算法迭代不用碰固件，坏处是**实时边界从「板内」退到了「链路上」**——所以这套设计里，
一半的篇幅都在处理链路的抖动与丢包。

## 二、与 MCU 单机方案的三个差异

| | hyperdog_rtos_control | 本方案 |
|---|---|---|
| 实时边界 | MCU 内部，环路闭合在板上 | 跨 Linux/UART/MCU 三段，需底层吸收抖动 |
| 通信 | 私有 CAN 帧（自定义 ID + 校验） | XRCE-DDS Topic（标准化，可接 ROS 2 生态） |
| 足端轨迹 | 五次多项式（起止速度、加速度为 0） | 贝塞尔曲线（抬高摆动相、落地段减速缓冲） |
| 上位机 | 无（可选 Python 调试脚本） | 必需，跑 IK 与步态节点 |

## 三、关键设计点

1. **三段式接收，中断只搬数据**：DMA 批量接收 → 环形缓冲区 → FreeRTOS 队列 → 解析任务。
   中断里不做解析，避免高频串口中断抢占电机控制任务。
2. **时间戳 + 匀速插值**：上位机固定 100 Hz 下发并带时间戳，底层按本地时钟匀速插值执行，
   把「周期性到达但带抖动」的指令还原成连续运动。
3. **原生 PWM 取代扩展板**：原版开源方案用 STM32F407 Discovery + PCA9685（I²C 扩展 PWM），
   本方案改用 TIM1 / TIM8 高级定时器直接出 PWM，省掉 I²C 链路，多路同步性更好。
4. **角度软限幅**：下发角度在映射为 PWM 比较值之前先做上下钳位，防止机械结构超程撞机。
