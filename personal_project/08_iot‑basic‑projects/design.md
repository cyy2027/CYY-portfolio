# 工业物联网边缘网关（Linux+MCU 双芯片架构）设计文档

## 1. 需求概述

### 1.1 功能需求

1. ESP32 终端节点：采集现场传感器数据，上报边缘网关；接收网关下发控制指令执行动作。
2. RK3568 边缘网关：
   - 搭建本地 MQTT 消息代理，接收终端上报数据
   - SQLite 本地持久化存储，网络异常时缓存数据，网络恢复自动补传
   - Socket TCP 与 MCU 通信，下发控制指令，回读设备状态
   - Web 网页看板，实时展示传感器、设备状态
3. 端‑边联调，支持多终端同时接入。

### 1.2 非功能需求

- 网络断线不丢失采集数据；网络恢复自动补发历史缓存
- 支持多台 ESP32 节点接入，设备消息隔离
- 数据上报延迟可控，具备基础异常处理、重连机制

## 2. 总体架构设计

三层架构：终端采集层、边缘网关层、上层云（可选）

1. **终端采集层‑ESP32‑S3**
FreeRTOS 多任务：传感器采集任务、MQTT 网络任务、指令解析任务；NVS 保存配网参数。
上报 Topic：`device/{dev_id}/upload`
接收控制 Topic：`device/{dev_id}/cmd`
2. **边缘网关层‑RK3568 Linux**

- MQTT Broker：负责接收终端消息，内部转发
- 业务服务程序：C 语言应用程序，订阅 MQTT 主题，接收设备数据；写入 SQLite 数据库；处理缓存补发逻辑；提供 Socket 服务与 MCU 交互
- Web 服务：读取 SQLite 数据，前端看板渲染实时数据

3. 通信链路

- ESP32 ↔ RK3568：MQTT over Wi‑Fi（主要上报链路）
- RK3568 ↔ MCU 备选：TCP Socket，用于大报文、特殊控制指令

## 3. 模块详细设计

### 3.1 ESP32 终端模块

1. 采集任务：周期性读取传感器数据，组装 JSON 报文，通过 MQTT 发布。
2. MQTT 客户端：实现断线重连逻辑；NVS 保存 Broker 地址、设备 ID。
3. 指令解析：订阅命令 Topic，收到网关下发指令，解析后执行对应控制动作，返回执行状态。

> 
> 报文示例（上报）

```
{
  "dev_id":"esp32_01",
  "temp":25.6,
  "hum":62.1,
  "timestamp":1740000000
}
```

### 3.2 RK3568‑Linux 业务应用模块

1. MQTT 客户端模块：订阅所有设备上报 Topic；收到消息解析 JSON。
2. SQLite 缓存模块

- 数据表设计：设备 ID、数据内容、时间戳、补发状态标记。
- 正常网络：写入数据库，同时推送到 Web 展示；
- 网络异常：全部写入数据库，标记`status=0`待补发；
- 网络恢复：遍历表中 status=0 记录，重新转发，成功后修改 status=1。

3. Socket TCP 服务模块：监听端口，接收 MCU 连接；定义报文头部 + 长度 + CRC 校验，处理粘包。
4. Web 数据服务：查询 SQLite 最新数据，提供 HTTP 接口，前端页面轮询渲染看板。

## 4. 关键算法与机制：断线缓存补发机制

1. 网关收到终端上报数据，**优先落盘 SQLite**，再做转发展示。
2. 链路状态检测：心跳包判断终端是否在线。
3. 网络恢复触发补发：遍历未发送成功记录，逐条重新处理。
4. 补发完成更新数据库标记；设置旧数据老化清理，防止数据库无限膨胀。

## 5. 遇到的问题与 Bug 记录（面试重点，必看）

1. **MQTT 重连后历史数据丢失**
现象：Wi‑Fi 短暂断开，重连成功，断开期间采集的数据直接丢失。
解决：增加 SQLite 本地缓存层，收到数据先存库，再转发，依靠数据库做数据兜底。
2. **TCP Socket 粘包问题**
现象：多条 MCU 报文合并接收，JSON 解析失败。
解决：自定义帧头 + 长度字段，按帧解析，不直接按 JSON 分割。
3. SQLite 频繁写入锁冲突
现象：MQTT 回调、Socket 服务两个线程同时写数据库，偶现报错。
解决：数据库操作加互斥锁，保证同一时刻只有一处写操作。
4. Web 看板数据卡顿
现象：数据库查询频繁，页面刷新卡顿。
解决：增加内存缓冲，不要每次页面请求都全量查询数据库。

## 6. 测试结果

- 多台 ESP32 终端同时接入，消息收发正常；
- 人为断开 Wi‑Fi 模拟断网，设备继续采集，网关本地缓存；恢复网络，历史数据自动补发；
- Web 看板实时刷新传感器数据，端‑边‑云全链路跑通。
