
# LVGL嵌入式GUI实战：内存管理、页面切换、帧率优化、内存泄漏排查
📄 文档路径：docs/lvgl-gui-notes.md
> 标识：🔴
> 配套项目：BMS、工业物联网边缘网关、温控面板
> 定位：MCU+FreeRTOS 平台 LVGL 量产稳定方案，面向嵌入式底层开发；侧重资源受限设备稳定性，不追求复杂动画效果。
> 包含：LVGL 内存池机制、页面生命周期、屏幕撕裂与帧率优化、RTOS 多任务协同、内存泄漏定位、触摸屏输入调试、伪代码与故障排查思路。


## 1 项目背景
很多嵌入式设备需要本地人机交互面板：参数显示、故障告警、菜单设置。
直接在主循环裸机跑LVGL容易出现：页面切换卡顿、内存越界、内存泄漏、屏幕撕裂、和RTOS任务抢占冲突。
本笔记基于STM32 + FreeRTOS + LVGL8.2 版本总结，聚焦资源受限MCU上的GUI工程落地。

## 2 核心原理
### 2.1 LVGL内存池（lv_mem）
LVGL默认自带内存池，不是直接调用`malloc/free`。
- 内存池预先在RAM划出一块连续内存，所有控件、画布、字符串都从这里申请；
- 优点：碎片可控、分配速度稳定；缺点：内存池容量固定，分配失败返回NULL；
- 关键：**动态控件必须手动销毁，静态控件不需要释放**。

> 易错点：
> 很多人混用 `lv_mem_alloc` 和标准库 `malloc`，调试时很难定位内存越界。

### 2.2 页面切换的两种模式
1. 静态页面：页面控件一次性全部创建，常驻内存，切换只修改可见性；适合页面少、控件简单的场景。
2. 动态页面（推荐量产）：打开页面时`lv_obj_create`，退出页面时整体删除页面根对象，子对象自动递归释放；适合多菜单、参数配置面板，节省RAM。

### 2.3 刷新机制 & 屏幕撕裂
LVGL采用**脏区刷新**，只重绘变化区域；
MCU屏幕一般是SPI/OLED并口，刷新和屏幕扫描时序不同步就会出现撕裂（上半屏旧画面、下半屏新画面）。
两种方案：
- 双缓冲：两块显存，画完一整帧再交换；RAM开销大；
- 行缓冲 + 同步刷新：小屏常用，在显示驱动`lv_disp_flush_ready`同步时序。

### 2.4 RTOS下LVGL任务调度要点
LVGL本身不是线程安全！
✅ 正确做法：**所有LVGL API只在同一个任务里面调用**，其它任务不能直接操作控件。
其它任务（采集、CAN、MQTT）如果要更新UI，发送消息队列给GUI任务，由GUI任务统一调用LVGL接口刷新。
> 禁止：在中断、别的任务里直接`lv_label_set_text`，极易出现内存破坏、HardFault。

### 2.5 输入设备（触摸屏）
触摸屏输入是异步事件，LVGL输入驱动上报坐标，内核放到输入队列，GUI主循环处理。
常见问题：抖动、长按、重复触发、触点漂移。

## 3 典型工程伪代码
```c
// GUI任务：唯一允许调用LVGL接口的任务
void gui_task(void *arg)
{
    lv_init();
    lv_disp_drv_init(&disp_drv);
    disp_drv.flush_cb = disp_flush;
    lv_disp_drv_register(&disp_drv);

    // 注册触摸屏输入设备
    lv_indev_drv_init(&indev_drv);
    indev_drv.type = LV_INDEV_TYPE_POINTER;
    indev_drv.read_cb = touch_read;
    lv_indev_drv_register(&indev_drv);

    // 创建初始页面
    ui_home_page_create();

    while(1)
    {
        // 处理LVGL内核
        lv_timer_handler();
        // 从消息队列接收外部数据（电压、SOC、故障标志）
        if(xQueueReceive(gui_queue, &gui_msg, pdMS_TO_TICKS(5)) == pdPASS)
        {
            // 只在这里更新UI控件
            ui_refresh_by_msg(&gui_msg);
        }
    }
}

// 页面切换：动态页面，退出时销毁根对象
void ui_switch_page(lv_obj_t *(*page_create)(lv_obj_t *parent))
{
    // 销毁旧页面根对象，自动释放所有子控件
    if(ui_current_page != NULL)
    {
        lv_obj_del(ui_current_page);
        ui_current_page = NULL;
    }
    // 创建新页面
    ui_current_page = page_create(lv_scr_act());
}
```

## 4 高频踩坑记录（面试高频）
### 坑1：动态页面不销毁，持续内存泄漏
现象：反复切换菜单，LVGL内存占用持续上涨，一段时间后`lv_mem_alloc`返回NULL，界面卡死、花屏。
原因：只隐藏控件，没有`lv_obj_del`；或者只删子控件，忘记删除页面根对象。
解决：统一页面管理，切换页面时删除页面根对象，LVGL自动递归释放子控件；开启LVGL内存统计，定时打印内存池剩余大小。

### 坑2：多任务直接调用LVGL API，随机HardFault
现象：偶发死机，抓HardFault栈看不出明显规律，复现概率低。
原因：采集任务、CAN任务直接调用`lv_label_set_text`，并发访问LVGL全局内存结构，破坏链表。
解决：所有UI变更通过消息队列发给GUI任务，GUI任务独占LVGL调用权。

### 坑3：屏幕刷新撕裂、画面花块
现象：页面刷新时一半旧画面一半新画面，拖动控件明显撕裂。
原因：单缓冲，刷新函数还没画完，屏幕就开始扫描输出。
解决：小屏OLED：缩短脏区；彩屏尽量启用双缓冲，等待`flush_ready`同步。

### 坑4：LVGL定时器过多，CPU占用高、帧率下跌
现象：打开动画页面后，系统整体卡顿，ADC、PID闭环周期不稳。
原因：大量lv_timer高频回调，和高优先级控制任务抢占CPU。
解决：
1. 非关键动画降低定时器周期；
2. 页面退出时，手动删除页面内创建的lv_timer；
3. GUI任务优先级**低于PID、采集、保护任务**，保证控制闭环优先。

### 坑5：触摸屏抖动、多次误触发
现象：触摸一次，页面连续跳转多次。
原因：触摸屏原始采样噪声，LVGL输入驱动没有滤波。
解决：在touch_read回调里做滑动滤波；开启LVGL长按/点击去抖动参数。

### 坑6：RAM不足，LVGL内存池分配失败
现象：能编译下载，跑起来创建控件直接失败。
原因：MCU RAM紧张，内存池开太大挤占堆、栈、DMA缓冲区。
解决：
1. 裁剪LVGL配置：关闭不需要的组件、动画、字体；
2. 使用压缩字体，不要放超大字库；
3. 动态页面优先，不用的页面及时释放。

## 5 调试手段
1. 开启`LV_MEM_ENABLE_STATS`，定时打印内存最大占用、剩余内存，定位泄漏；
2. 开启LVGL日志，打印分配失败、控件创建报错；
3. 逻辑分析仪/示波器看SPI屏幕刷新时序，排查撕裂；
4. 任务栈监控：GUI任务栈溢出会直接花屏、死机。

## 6 调优总结（背诵版）
1. 线程安全：**LVGL只在单一任务调用**，跨任务UI更新走消息队列；
2. 内存管理：动态页面创建根对象，切换页面删除根对象，防止内存泄漏；利用LVGL自带内存统计监控；
3. 调度优先级：GUI任务优先级低于控制、保护、采集任务，不能抢占闭环；
4. 刷新优化：脏区刷新，有条件上双缓冲解决撕裂；
5. 资源裁剪：关闭无用组件、精简字体，适配小RAM MCU。
