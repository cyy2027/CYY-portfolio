## 1. 通信概述
HyperDog 采用 CAN2.0B 标准，波特率 1Mbps，作为主控板与4个关节伺服板唯一实时控制链路。
- 拓扑：**1个主控（Master） + 4个关节伺服（Slave）**，总线并联；
- 节点定义：FR（前右）、FL（前左）、RR（后右）、RL（后左）；
- 通信模式：**主控周期下发指令，关节被动周期回传状态**；不使用主动上报（除故障紧急帧）；
- 实时性约束：主控下发周期 1kHz；关节状态回传周期 500Hz；
- 设计目标：低抖动、可校验、支持掉线检测、故障上报、总线短路/干扰自恢复。

> 原则：控制帧精简，只携带闭环必需信息；非实时日志、调试数据不走CAN控制总线，改用WiFi/串口遥测通道。

## 2. CAN ID分配方案（扩展帧 29bit，标准帧也可按需切换）
> 采用静态ID分配，ID自带节点号+帧类型，便于过滤器配置，减少CPU解析开销。
| 帧类型 | 基础ID | 节点偏移 | 说明 |
| ---- | ---- | ---- | ---- |
| 主控→关节：目标控制帧 | 0x100 | +0~3 | 0x100 FR / 0x101 FL / 0x102 RR / 0x103 RL |
| 关节→主控：状态反馈帧 | 0x200 | +0~3 | 0x200 FR / 0x201 FL / 0x202 RR / 0x203 RL |
| 关节→主控：紧急故障上报帧 | 0x300 | +0~3 | 过流、过热、堵转、硬件故障，高优先级 |
| 主控广播帧（全部关节） | 0x400 | 无偏移 | 全局使能、急停、复位、零位标定指令 |

过滤器配置要点：
- 主控：接收全部4路关节状态帧 + 故障帧；
- 关节伺服：只接收属于自己的单播控制帧 + 全局广播帧；
- 过滤使用掩码过滤，避免软件轮询判断ID，降低中断开销。

## 3. 帧格式定义（小端，8字节有效载荷）
### 3.1 主控下发：关节目标控制帧（0x100~0x103）
| 字节 | 含义 | 说明 |
| ---- | ---- | ---- |
| 0~1 | 目标角度 int16 | 单位：0.01°，范围 ±18000（±180°） |
| 2~3 | 目标角速度 int16 | 单位：0.1°/s |
| 4~5 | 目标力矩 int16 | 力矩环目标，可用于阻抗控制 |
| 6 | 控制模式 uint8 | 0:角度环 1:速度环 2:力矩环 3:脱机使能 |
| 7 | 保留+校验位 | bit7=1 代表本帧有效 |

> 下发逻辑：主控1kHz依次向4个关节发送控制帧，保证4腿时序对齐。

### 3.2 关节回传：状态反馈帧（0x200~0x203）
| 字节 | 含义 | 说明 |
| ---- | ---- | ---- |
| 0~1 | 当前角度 int16 | 编码器实测角度 0.01° |
| 2~3 | 当前电流 int16 | 采样电流，用于触地判断、过流保护 |
| 4~5 | 温度 uint16 | 伺服板MOS/电机温度 |
| 6 | 状态字 uint8 | bit0:在线；bit1:闭环就绪；bit2:限位；bit3:堵转 |
| 7 | 故障码 uint8 | 0=正常；非0对应故障类型 |

### 3.3 关节紧急故障帧（0x300~0x303）
| 字节 | 含义 |
| ---- | ---- |
| 0 | 故障类型 | 1过流、2过热、3硬限位、4编码器丢失、5FOC失锁 |
| 1~7 | 预留 | 故障附加信息（瞬时电流、温度） |

> 紧急帧不受500Hz周期限制，故障触发时立刻发送，抢占总线。

### 3.4 主控广播帧 0x400（全局指令）
| 字节 | 含义 |
| ---- | ---- |
| 0 | 广播命令码 | 0x01:使能所有关节；0x02:紧急急停；0x03:零位标定；0x04:软复位 |
| 1~7 | 参数预留 |

## 4. 收发时序与同步策略
1. 主控定时器1ms触发发送任务，依次发送4路关节控制帧；
2. 关节收到控制帧后，**立即更新目标值，启动本次闭环计算**，500Hz周期打包状态回传；
3. 同步方式：**时间基准由主控统一驱动**，关节不独立维护步态相位；步态相位由主控Gait_Scheduler统一管理；
4. 超时判定：主控对每个关节设置2ms状态超时；超时则标记该关节掉线，进入故障逻辑。

> 带宽评估：单帧约130bit（ID+CRC+间隙），4路控制帧1ms内发送，总线负载控制在40%以内，预留干扰重传余量。

## 5. 总线容错与保护机制（重点面试考点）
1. **节点掉线检测**：主控维护4个关节的接收心跳计时器，超过阈值判定掉线；
2. **CAN错误状态管理**：读取CAN ESR寄存器，区分主动错误、被动错误、总线关闭；总线关闭时自动软件复位CAN外设，尝试恢复；
3. **帧有效性校验**：帧内标志位+业务层校验，区分空帧、残留旧帧；
4. **急停广播优先**：急停广播帧优先级高于所有控制帧，故障时立刻下发；
5. **禁止关节主动抢占总线**：正常状态仅周期回传，只有故障帧允许异步上报，防止总线风暴；
6. **总线隔离**：电源和CAN增加共模电感、TVS，降低电机PWM带来的电磁干扰。

## 6. 收发逻辑伪代码
```c
// 主控侧：CAN发送一帧关节目标指令
void HyperDog_CAN_SendJointTarget(uint8_t joint_id, float target_angle, uint8_t ctrl_mode)
{
    CanTxMsgTypeDef tx_msg;
    uint16_t can_id = 0x100 + joint_id;

    int16_t angle_raw = (int16_t)(target_angle * 100.0f);
    tx_msg.Data[0] = angle_raw & 0xFF;
    tx_msg.Data[1] = (angle_raw >> 8) & 0xFF;
    tx_msg.Data[6] = ctrl_mode;
    tx_msg.Data[7] = 0x80; // 有效标记

    HAL_CAN_AddTxMessage(&hcan1, &tx_msg, &tx_msg.Data, &tx_mailbox);
}

// 关节伺服侧：CAN接收中断回调，入队给任务解析
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    CanRxMsgTypeDef rx_msg;
    HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &rx_msg, rx_msg.Data);
    // 原始帧送入队列，不在中断里做FOC计算
    xQueueSendFromISR(g_joint_ctrl_queue, &rx_msg, NULL);
}
```

## 7. 实测踩坑记录
1. 下发顺序抖动：高优先级IMU中断抢占CAN发送，导致1kHz下发周期抖动，伺服闭环震荡；解决方案：合理分配中断优先级，CAN发送放在任务内，中断只做接收入队；
2. 总线风暴：早期设计故障时关节无限循环上报故障帧，直接打满总线；增加故障上报限流，同一故障100ms最多上报一次；
3. 多节点ID冲突：调试时两个伺服板烧录相同ID，总线报错；出厂增加ID烧录工具，上电读取板载ID；
4. 干扰丢帧：电机大功率运转时CAN偶尔丢帧；增加终端电阻检查、共模滤波，同时业务层增加心跳超时兜底，不依赖单帧；
5. 新旧帧覆盖：队列长度不足，新帧覆盖未解析的旧目标帧；主控侧使用双缓冲，关节侧队列长度至少预留4帧缓冲。
