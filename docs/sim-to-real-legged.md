# Sim-to-Real：从 Isaac Gym 训练到 Qmini 真机落地

> 📄 文档路径：`docs/sim-to-real-legged.md`

> ✍️ 强化学习策略在仿真里走得很稳、一上真机就摔，这是物理世界的常态而不是意外。本文拆这个差距的来源：观测/动作空间怎么定义、奖励怎么设计才不"骗自己"、域随机化加哪些项、真机侧 PD 参数怎么桥接、以及怎么量化"迁移成功"。

> ⚠️ **文档定位**：以 [Unitree Qmini](https://github.com/unitreerobotics/Qmini)（11 自由度双足）与山大 VSISLab 的 [RoboTamer4Qmini](https://github.com/vsislab/RoboTamer4Qmini)（Isaac Gym + PPO）为参照的**方法梳理**，本机未上机训练。文中训练规模与时延为**目标值**。仿真与硬件的分工见[《大脑—小脑异构架构》](./embodied-brain-body-arch.md)。

---

## 一、为什么必须仿真训练

真机训练不可行，原因不是"慢"，而是三条硬约束：

1. **样本代价**。PPO 收敛需要千万级步数。真机 50 Hz 采一步，一千万步是 55 小时**连续不摔**——有摔一次就重置的话，实际耗时是天文数字。
2. **重置成本**。摔倒要人工扶起来、检查结构件、可能换件。仿真是毫秒级 `reset()`。
3. **安全性**。训练初期的策略是随机动作，真机上等于随机给 11 个电机发指令。

Isaac Gym 的价值在于**把大量环境塞进一张 GPU**：Qmini 这种 11 自由度的小双足，单卡并行几千个环境是常规做法，几小时能跑完一轮训练。这就是为什么这类开源项目的训练管线几乎都长在 Isaac Gym 上。

## 二、观测与动作空间：接口定义错了，后面全白搭

### 2.1 观测（policy input）

双足平衡的最小充分集：

| 类别 | 具体量 | 维度 | 备注 |
|---|---|---|---|
| 本体感知 | 关节位置（相对零位） | 10 | 10 个腿部电机 |
| | 关节速度 | 10 | 由编码器差分或驱动器内部给出 |
| | 机身角速度（IMU 陀螺） | 3 | 最关键的一项，几乎不能缺 |
| | 机身姿态（投影重力向量） | 3 | 比欧拉角更好训，无万向锁 |
| | 上一拍动作 | 10 | 让策略知道"我刚做了什么"，抑制抖动 |
| 指令 | 线速度 / 角速度指令 | 3 | 由上层给定 |
| 相位（可选） | 步态时钟 sin/cos | 2 | 纯 RL 可不加，加了对步态周期更可控 |

三个设计要点：

1. **用投影重力向量代替欧拉角**。重力向量在机身坐标系下是 `[0,0,-1]` 旋转后的结果，天然无奇异点，网络学起来更顺。
2. **必须喂上一拍动作**。不喂的话，策略无法感知自己的输出历史，容易在相邻拍之间来回振荡（这是真机上"高频抖"的常见来源）。
3. **观测要做裁剪（clip）而不是归一化到"看不见的尺度"**。IMU 在落地冲击时会短时饱和，裁剪能让策略见到"极端值"而不是被归一化抹平。

### 2.2 动作（policy output）

两种常见形式：

| 形式 | 输出 | 优点 | 缺点 |
|---|---|---|---|
| 关节位置目标 | 10 维目标角 | 稳定、易部署 | 高频跟踪时对 PD 带宽要求高 |
| 关节力矩（含 PD 残差） | 10 维力矩 | 力控更直接 | 真机力矩环要求高，Qmini 的 8010 电机是否开放力矩模式需确认 |

**Qmini 这条路建议先用位置目标 + 驱动器内部 PD**。理由：Unitree 8010 是带 FOC 的一体化关节，位置/速度环在驱动器内部闭环，跑得比主控发力矩更稳；策略只负责给目标角，主控侧再做斜率限幅。这样部署链路短，出问题也容易定位是策略还是底层。

## 三、奖励设计：怎么避免"骗自己"

奖励函数是唯一由人指定的部分，也是最容易写出"仿真高分、真机摔跤"的地方。参考结构（示意）：

| 项 | 形式 | 权重 | 想约束什么 |
|---|---|---|---|
| 速度跟踪 | `exp(-‖v_cmd - v‖²/σ)` | 正，大 | 主目标 |
| 姿态保持 | `-‖g_xy‖²` | 负，中 | 别歪 |
| 机身高度 | `-(h - h*)²` | 负，中 | 别蹲别飘 |
| 关节加速度 | `-‖q̈‖²` | 负，小 | 动作平滑，直接对应真机抖 |
| 力矩/功率 | `-‖τ‖²` | 负，小 | 省电、降温 |
| 关节限位 | 越界重罚 | 负，大 | 别把机械结构顶坏 |
| 足端打滑（可选） | 接触点切向速度 | 负，小 | 步态更真实 |

三个坑：

1. **只罚速度不罚加速度**，训出来的策略会高频抖动。仿真里无所谓（物理引擎无噪声），真机上电机跟着抖，几小时就过热。关节加速度惩罚是 sim2real 的关键项，不是可选项。
2. **奖励项太多会互相打架**。超过 8 项、权重全靠手调，基本调不动。**先只留 3 项（速度跟踪、姿态、高度）跑通，再逐项加。**
3. **`exp()` 形式的跟踪项有饱和**，误差大时梯度几乎为零，策略学不到"从摔倒中恢复"。可以在训练早期用线性项，后期切 `exp`。

## 四、域随机化：随机什么，为什么随机

RoboTamer4Qmini 的做法（Isaac Gym + 域随机化 + 随机外部推力）是这类项目的标准配方。具体到项：

| 随机项 | 范围（经验值） | 为什么必须随机 |
|---|---|---|
| 机身/连杆质量 | ±10% | 3D 打印件填充率不一致，实际质量与 CAD 有偏差 |
| 质心位置 | ±2 cm | 电池、主控、线束的实际布置与模型不符 |
| 地面摩擦系数 | 0.4～1.2 | 瓷砖、地胶、草地差别巨大 |
| 电机强度（力矩常数） | ±10% | 同型号电机个体差异 + 温升衰减 |
| 关节零位偏移 | ±3° | 装配误差，**这一项不做，真机一定歪** |
| 控制延迟 | 0～20 ms | Linux 调度 + 链路 + 驱动器内部延迟 |
| 观测噪声 | 陀螺 ±0.05 rad/s 等 | IMU 真实噪声水平 |
| 外部推力 | 随机方向、50～150 N、0.1 s | 抗扰能力，也是评估指标 |
| 地形（可选） | 高度场 0～3 cm | 真实地面不是理想平面 |

**延迟随机化最容易被跳过，但最要命。** 仿真里观测到动作是零延迟的，真机上是 20～40 ms。策略如果按零延迟学，在真机上相当于一直用"过时的信息"做决策，表现是相位滞后、越走越晃。把延迟随机进去，策略会自己学会"提前一点"。

> 注意：域随机化的范围不是越大越好。范围过宽会让策略变得过度保守（走得很慢很僵）。**做法是逐项消融**：先全开，训一版；然后每次关掉一项，看真机成功率变化，找出真正重要的项，再围绕它扩范围。

## 五、真机侧：PD 参数与"最后一公里"

仿真里的 PD 是理想化的：力矩立即响应、无死区、无摩擦。真机的 8010 电机有自己的位置环参数。这就是 RoboTamer4Qmini 里 `tune_pid.py` 存在的原因 —— **桥接仿真的 PD 增益与真机驱动器参数**。

做法通常是：

1. 在真机上单独测一个关节的阶跃响应（给 5° 阶跃，记录角度曲线）；
2. 调驱动器内部增益，让响应接近仿真里设定的自然频率与阻尼比；
3. 把测出来的等效增益写回仿真，重新训一遍（或至少微调）。

顺序不能反：**先对齐单关节，再训整机**。整机调参时任何"说不清是策略问题还是驱动器问题"的现象，根源都在这一步没做。

另外两个真机特有的补偿：

- **重力补偿**：仿真里重力是精确已知的，真机的连杆质量有偏差。可以加一个简单的重力前馈项，或用低增益积分项吸收。
- **摩擦与齿隙**：8010 有减速器，齿隙在换向时造成死区。策略如果对零位敏感，会表现为站立时轻微晃动。

## 六、怎么算"迁移成功"

别用"能走了"这种描述。三个可量化指标：

| 指标 | 定义 | 目标（Qmini 级，站立/慢走） |
|---|---|---|
| 任务成功率 | 指令下连续行走 N 秒不摔的比例 | ≥ 80%（平地，无扰） |
| 抗扰成功率 | 施加 50～150 N 侧向推力后恢复的比例 | ≥ 60% |
| 性能衰减 | 真机 vs 仿真的速度跟踪 RMSE 比值 | ≤ 2.0 |

第三个指标最诚实地反映 sim2real 差距。比值在 1.2 以内说明迁移很好；大于 3 说明某个随机项没覆盖到（通常是延迟或摩擦）。

## 七、这条路的现实约束

写清楚，免得把它想简单：

1. **算力**：Isaac Gym 训练需要一块像样的 NVIDIA GPU（≥ 8 GB 显存）。纯 CPU 训练不现实。
2. **调参周期**：一个策略从奖励设计到收敛，正常要几十轮迭代，每轮几小时。这是这个方向真正的成本。
3. **真机调试风险**：第一次上电必须吊装或加软垫，且必须有人能随时断电。策略输出的第一个动作可能是任意值。
4. **可复用性**：换机器人（双足换四足）时，观测/动作空间、奖励权重要重做，只有管线能复用。别指望"训一次到处跑"。
