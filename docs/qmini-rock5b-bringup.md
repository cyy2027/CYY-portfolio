# Qmini + Rock 5B 上板路线：从开箱到策略闭环

> 📄 文档路径：`docs/qmini-rock5b-bringup.md`

> ✍️ 一份"还没买就先想清楚"的落地路线：买什么、怎么供电、接口怎么接、分几步验证、每一步失败退到哪。开源项目给的是零件和代码，不给的是**把两块板子接成一台机器人的顺序** —— 这份文档补的就是这一块。

> ⚠️ **文档定位**：本路线**尚未执行**，硬件未采购。所有步骤基于 [unitreerobotics/Qmini](https://github.com/unitreerobotics/Qmini) 公开资料与 [RoboTamer4Qmini](https://github.com/vsislab/RoboTamer4Qmini) 部署流程整理，验收指标为目标值。不做"已完成"的表述。

---

## 一、要买什么

Qmini 官方开源了完整 BOM，核心构成：

| 项 | 规格 | 数量 | 说明 |
|---|---|---|---|
| 关节电机 | Unitree GO-M8010-6 | 11 | 10 个驱动双腿与躯干，1 个在颈部预留扩展 |
| 电池 | Unitree GO1 标准电池包 | 1 | 24 V 级，含 BMS |
| 主控（原版） | 树莓派 4B / 4 GB | 1 | 官方参考主控 |
| 通信 | USB 转 485 适配器 | 1 | 电机总线是 RS485 物理层 |
| 惯性测量 | IMU 模块（N100 类） | 1 | 姿态反馈 |
| 手柄 | PS4 / 蓝牙手柄 | 1 | 手动控制与急停 |
| 结构件 | 3D 打印（PLA/PETG） | — | STEP 文件全开，无需 CNC |

**成本结构要提前认清**：11 台 8010 是整机成本的主体，结构件反而是零头（几卷耗材）。所以"3D 打印降成本"只降了机械部分，动力系统降不下来。这也是它和 Open Duck Mini 那类舵机方案的根本差异 —— 后者便宜一个数量级，但执行器性能也差一个数量级。

**替换项**（本方案要做的）：

| 原版 | 换成 | 动机 |
|---|---|---|
| 树莓派 4B | **Rock 5B（RK3588）** | 需要 NPU 跑策略；树莓派纯 CPU 推理稍大网络就掉帧 |
| ONNX Runtime (CPU) | **RKNN runtime (NPU)** | 同模型 INT8 推理延迟降一个量级 |

## 二、三件必须先确认的事

采购前不确认这三条，钱可能白花：

### 2.1 电机总线是否开放

Qmini 的关节走 Unitree 自家协议（RS485 物理层）。需要确认：

- 是否提供公开的协议文档 / SDK？
- 能否**绕过原厂主控**，用第三方主控（Rock 5B）直接驱动？
- 电机是否支持位置 / 速度 / 力矩三种模式，模式切换怎么触发？

**若不开放**，整条"Rock 5B 当大脑"的路线要改成"Rock 5B 只做上层、原厂主控做执行"，两域之间再加一层 —— 架构复杂度上升，但并非不可行。

### 2.2 部署 SDK 的维护状态

RoboTamer4Qmini 的配套 SDK 仓库在 README 里标注了不再维护（not maintained）。这意味着：

- 遇到问题没有上游支持，要自己读代码；
- 依赖的 ONNX Runtime 版本可能较旧，换 RKNN 时要自己重写推理后端；
- MIT 许可，fork 自维护是被允许的 —— 但要预估这部分工作量。

### 2.3 Rock 5B 的供电能力

Rock 5B 需要 5 V / 4～5 A（满载带外设时更高），Qmini 电池是 24 V 级。必须加一级 **DC-DC 降压（24 V → 5 V，≥ 5 A）**，且要注意：

- 电机启动瞬间的电流冲击会拉低母线，可能把 Rock 5B 拉到欠压重启；
- 建议 Rock 5B 单独一路 buck，并在输入端加足够容量的电解电容；
- **不要**从电机的 5 V 输出取电，那个口带不动。

## 三、分阶段路线

每一阶段都有明确验收口和失败退路。**顺序不可跳**——跳步的典型后果是"说不清是策略问题还是链路问题"。

```text
P0 结构组装        → 硬件能站（不上电驱动）
P1 原厂链路跑通    → 树莓派 + 官方 SDK，能站、能走
P2 换大脑          → Rock 5B 接管，通信打通，能站
P3 NPU 策略闭环    → 预置策略上 NPU，能按指令走
P4 自训练策略      → 自己训的策略替换，做域随机化消融
```

### P0：结构组装（1～2 天）

| 项 | 内容 |
|---|---|
| 做什么 | 按 `Qmini_DIY.pdf` 组装 11 个电机与结构件，走线 |
| 验收 | 断电状态下手动活动各关节，无卡滞、无干涉；整机放平能站稳 |
| 失败退路 | 打印件尺寸偏差 → 校准打印机 / 重打；电机编号与 URDF 对不上 → 先建映射表 |

> 这一步最容易忽略的是**零位**。组装完不标定零位，后面所有角度都是错的，且现象是"策略一上就摔"，很容易误判成策略问题。

### P1：原厂链路跑通（2～3 天）

| 项 | 内容 |
|---|---|
| 做什么 | 树莓派刷系统 → 装官方 SDK → 用预置策略或手动模式让机器人站起来、走两步 |
| 验收 | 能稳定站立 ≥ 60 s；手柄控制下能前后走、能停 |
| 失败退路 | 通信不通 → 查 USB-485 设备号与波特率；电机不使能 → 查使能时序与供电 |

**这一步是整个项目的"基线"**。只有原厂方案跑通了，后面换板子出问题时才有对照物。跳过这一步直接上 Rock 5B，等于同时引入两个未知量。

### P2：换大脑（3～5 天）

| 项 | 内容 |
|---|---|
| 做什么 | Rock 5B 刷 Ubuntu → 装 USB-485 驱动 → 移植通信层 → 跑通"读关节状态 + 发目标角" |
| 验收 | 能读到 11 个关节的角度/速度；能下发目标角让机器人保持站立 ≥ 30 s |
| 失败退路 | 通信时延过大 → 查 USB 轮询周期与进程优先级；站不稳 → 先降增益，用纯阻尼模式验证链路 |

关键动作：**先只做"透传"**。Rock 5B 读状态、上位机算角度、再下发 —— 不跑任何策略。这一步验证的是链路，不是算法。

### P3：NPU 策略闭环（3～5 天）

| 项 | 内容 |
|---|---|
| 做什么 | 预置策略 ONNX → RKNN 转换 → 板上推理 → 闭环 |
| 验收 | 单帧推理 ≤ 2 ms（目标）；50 Hz 闭环连续 10 min 不丢帧；机器人能按指令行走 |
| 失败退路 | 量化后动作抖 → 输出层改 int16/float；算子回落 CPU → 展平控制流；时延抖动大 → 锁频 + 绑核 |

转换细节见[《RK3588 NPU 部署链路》](./rk3588-npu-deploy.md)。

### P4：自训练策略（周期最长）

| 项 | 内容 |
|---|---|
| 做什么 | Isaac Gym 训练自己的策略 → 域随机化消融 → 真机迁移 |
| 验收 | 平地行走成功率 ≥ 80%；侧向推力 50～150 N 后恢复率 ≥ 60% |
| 失败退路 | 迁移效果差 → 逐项关随机化找关键项；完全不行 → 缩小任务域（先原地站立抗扰） |

方法见[《Sim-to-Real》](./sim-to-real-legged.md)。

## 四、风险与对策

| 风险 | 可能性 | 影响 | 对策 |
|---|---|---|---|
| 电机协议不开放 | 中 | 高（架构要改） | 采购前发邮件/提 issue 确认 |
| SDK 不维护，依赖版本冲突 | 高 | 中 | fork 自维护，锁定依赖版本 |
| Rock 5B 供电不足导致重启 | 中 | 高 | 独立 buck + 大电容；实测满载电压跌落 |
| 零位标定误差导致策略失效 | 高 | 中 | P0 阶段就用外部工具核对角度 |
| 3D 打印件强度不足（摔倒断裂） | 中 | 低 | PETG 代替 PLA；关键件加填充率 |
| 训练算力不足 | 中 | 中 | 先用预置策略验证链路，训练另开资源 |
| 时间投入超预期 | 高 | — | P2 完成即可作为"链路打通"的成果，不必强求 P4 |

最后一条值得单独说：**这套路线的价值可以在 P3 兑现**。跑通"NPU 策略闭环"已经能证明大脑-小脑架构成立，不必等自训练策略收敛。把里程碑切在这个位置，比"一定要训出自己的策略"更务实。

## 五、和已有项目的衔接

| 本路线需要的模块 | 已有基础 |
|---|---|
| 多关节指令下发、限幅、故障降级 | 01 四足主控固件（CAN 主从、1 kHz 下发、分级保护） |
| 单关节闭环、编码器反馈 | 03 STM32 无刷电机 FOC |
| Linux 侧部署、跨进程通信、断线重连 | 05 工业物联网边缘网关（RK3568，同架构不同代） |
| 非阻塞状态机与实时任务划分 | 01 / 04 / 07 的 FreeRTOS 实践 |

也就是说，除了"NPU 推理"与"RL 策略"这两块是新的，其余每一层都有已交付项目垫底。
