# STM32 HAL底层驱动开发踩坑总结
> 文档位置：`docs/tech-notes/stm32_driver_tips.md`
> 说明：本文为项目开发过程中整理的STM32 HAL库实战要点、常见坑与调试经验，**非完整工程**，案例来源于个人FOC电机、智能充电桩项目。

## 1. HAL库基础与SysTick
1. `HAL_Delay()` 基于SysTick定时器，默认在主循环使用；**中断内部禁止调用HAL_Delay**，会阻塞系统甚至卡死。
2. SysTick时钟源默认来自内核时钟，修改系统时钟后，SysTick自动重配置；但如果在时钟初始化前调用`HAL_Delay`会产生延时不准。
3. `HAL_Init()` 内部会初始化SysTick、NVIC分组；**必须放在main函数最开头**。
4. 踩坑：使用外部高速晶振HSE时，若晶振未起振，程序卡在`HAL_Init`或`SystemClock_Config`，排查顺序：硬件晶振、负载电容、BOOT引脚。

## 2. GPIO驱动要点
1. 推挽输出 `GPIO_MODE_OUTPUT_PP`：驱动能力强，适合继电器、LED；
2. 开漏输出 `GPIO_MODE_OUTPUT_OD`：本身无高电平，需要外部上拉，适合I2C总线；
3. 输入模式：`GPIO_MODE_INPUT`，上拉/下拉配置，按键常用上拉输入；浮空输入容易受干扰，不推荐直接用于按键。
4. 注意：复用功能引脚（SPI/I2C/UART），必须配置为复用模式，不能配置成普通GPIO。
5. 踩坑：多个IO共用同一个端口，修改ODR寄存器时，不要直接赋值，使用位掩码操作，避免误修改其他引脚。
```c
// 推荐
GPIOA->ODR |= GPIO_PIN_0;
GPIOA->ODR &= ~GPIO_PIN_0;
// 不推荐（会覆盖同端口其他引脚状态）
GPIOA->ODR = GPIO_PIN_0;
```

## 3. 外部中断 EXTI
1. 外部中断引脚，**同一GPIO Pin号只能映射到一条EXTI线**，例如PA0/PB0不能同时作为外部中断。
2. 中断回调函数 `HAL_GPIO_EXTI_Callback` 是弱函数，重写时注意判断引脚。
3. ❗中断回调函数内代码要简短，**禁止在回调里执行耗时操作、printf、延时**；只做标志位置位，业务逻辑放到主循环处理。
4. 触发方式：上升沿、下降沿、双边沿；机械按键必须软件消抖，中断只做触发标志。

## 4. UART串口（HAL库高频踩坑点）
1. `HAL_UART_Receive_IT` 中断接收：HAL库单次中断只能接收1字节，接收完需要在回调里**再次调用`HAL_UART_Receive_IT`开启下一次接收**，否则收不到后续数据。
2. 推荐业务方案：环形缓冲区。中断里把数据存入ring buffer，主循环解析帧，避免在中断内解析长报文。
3. 波特率误差：HSE时钟不准，会导致串口乱码；优先核对系统时钟树。
4. 踩坑：不要在中断里调用`HAL_UART_Transmit`，会阻塞中断；大批量发送建议DMA。

## 5. I2C / SPI
### I2C
- 硬件I2C在HAL库容易出现死锁（SDA被拉低），工程中很多场景会改用软件模拟I2C，稳定性更高。
- 硬件I2C注意：从机地址、ACK信号，超时处理，防止程序卡死在等待应答。
### SPI
- SPI模式：CPOL/CPHA，主从必须完全一致，否则通信数据全乱。
- NSS片选：软件控制GPIO作为片选更灵活；硬件NSS容易出现时序问题。
- 高速SPI注意DMA搬运，减少CPU占用。

## 6. ADC + DMA（FOC电机项目大量使用）
1. ADC连续转换 + DMA循环搬运，非常适合电机电流电压采样。
2. DMA内存地址：如果是全局数组，地址固定；**局部数组不能用于DMA目标缓冲区**（栈内存，不稳定）。
3. ADC采样校准：`HAL_ADCEx_Calibration_Start(&hadc1)`，必须在ADC开启前执行，提升采样精度。
4. 踩坑：ADC输入电压超过参考电压会损坏芯片；增加分压和保护二极管。
5. DMA循环模式：持续采样，DMA自动覆盖缓冲区，可以使用双缓冲做数据处理。

## 7. 系统时钟树配置
1. HSI内部RC时钟精度差，适合简单调试；量产尽量使用HSE外部晶振。
2. PLL倍频配置错误会导致外设（UART、ADC）工作异常。
3. APB预分频：APB1最大时钟限制，定时器时钟会根据APB分频自动翻倍，容易混淆。
> 案例：FOC项目定时器PWM生成，因APB分频理解错误，PWM频率和预期不一致。

## 8. NVIC 中断优先级
1. STM32中断分组由`HAL_Init`配置，**整个工程只能使用一种分组**，不要多处修改`HAL_NVIC_SetPriorityGrouping`。
2. 抢占优先级：高抢占优先级可以打断低抢占优先级中断；子优先级只在同时触发时决定执行顺序，**不能互相打断**。
3. 设计原则：
    - 紧急硬件故障、电机过流：高抢占优先级
    - 串口、按键等：较低优先级
4. 禁忌：不要把所有中断都设为最高优先级，容易造成中断嵌套风暴。

## 9. 常见Bug汇总
1. 局部大数组放在栈中 → 栈溢出，程序随机死机。解决：改为`static`全局。
2. 中断共享变量，未加`volatile`，编译器优化导致变量读取异常。
```c
volatile uint8_t uart_rx_flag = 0;
```
3. 忘记开启外设时钟（`__HAL_RCC_XXX_CLK_ENABLE()`），外设完全不工作，这是新手最高频错误。
4. 复用功能引脚，忘记配置GPIO为复用模式，外设无输出。

## 10. 调试手段
1. 断点调试：中断内不建议长时间断点，容易破坏时序。
2. 用GPIO翻转电平，测量示波器观察代码执行耗时（比printf更精准）。
3. 看门狗：长时间卡死场景加入独立看门狗，异常自动复位。
