
# 调试工具实战：J-Link、逻辑分析仪、串口调试技巧
> 文档位置：`docs/tech-notes/debug_tool_practice.md`
>
> 说明：本文为项目开发整理的硬件调试工具实战经验与排错思路，**非完整工程源码**，案例来源于FOC电机、智能充电桩项目。

## 1. J-Link 基础调试
1. 下载方式：支持SWD接口，接线仅需要VCC、GND、SWDIO、SWCLK；相比JTAG接线更少，是STM32最常用方案。
2. 断点使用：**中断服务函数内不要长时间挂断点**，暂停会破坏硬件时序，容易导致总线异常、电机失控。
3. 寄存器查看：调试模式下可以直接查看外设寄存器、NVIC、堆栈指针SP，快速定位配置错误。
4. 栈查看：通过SP寄存器判断栈使用量，提前发现栈溢出隐患。
5. 踩坑：下载失败优先排查：SWD接线、复位电路、BOOT引脚、芯片供电。

## 2. 栈溢出定位方法
1. 栈溢出现象：程序随机HardFault，死机位置不固定，复现不稳定。
2. 定位手段：
    - 查看SP栈指针，判断是否超出栈空间范围
    - 开启内存填充（栈填充0xAA/0x55），运行后观察栈被占用上限
    - 使用RTOS自带栈水位监测（FreeRTOS `uxTaskGetStackHighWaterMark`）
3. 解决：把局部大数组改成`static`，调大启动文件栈大小，拆分复杂函数。

## 3. 逻辑分析仪（总线调试利器）
1. 适用场景：抓取I2C、SPI、UART、PWM等数字信号时序，定位通信异常、PWM波形错误。
2. 接线要点：GND共地非常重要，共地不良波形会有大量噪声，解析失败。
3. FOC项目用途：测量TIM输出PWM占空比、死区时间，观察相位时序。
4. 踩坑：采样率不足会导致波形混叠；采样率至少为信号最高频率5~10倍。

## 4. 串口调试（print调试）
1. 适用场景：打印变量状态、故障码，快速看程序运行流程。
2. 限制：`printf`执行耗时，**禁止在中断、高速控制循环内大量printf**，会干扰实时性。
3. 优化方案：
    - 使用环形缓冲区，后台DMA发送，不阻塞主逻辑
    - 生产固件可关闭串口打印，节省CPU资源
4. 踩坑：波特率、位序、停止位不匹配，或系统时钟不准，造成乱码。

## 5. 无打印调试方法（高实时性项目推荐）
高实时控制项目（FOC电机）不适合大量串口打印，推荐以下低成本方案：
1. GPIO翻转：代码关键点拉高/拉低IO，示波器测量电平，计算代码执行耗时。
2. LED状态机：不同LED闪烁模式，代表不同故障状态（过流、超时、就绪）。
3. 变量存入固定内存地址，停机后J-Link直接读取内存。

## 6. HardFault 崩溃定位
1. 常见触发原因：数组越界、野指针、栈溢出、非对齐内存访问、外设寄存器非法写入。
2. 定位步骤：
    - 进入HardFault中断，读取LR、PC寄存器
    - 根据PC跳转地址，找到崩溃对应的代码行
    - 查看栈回溯，找到函数调用链
3. 工程建议：HardFault中断内保存关键故障信息，方便事后复盘。

## 7. 看门狗故障复位调试
1. 独立看门狗IWDG：由内部RC时钟驱动，主时钟失效依旧可以工作；适合卡死自动复位。
2. 窗口看门狗WWDG：可以检测程序跑飞、任务执行超时。
3. 调试踩坑：开启看门狗后，断点暂停时看门狗依旧在计数，会直接触发芯片复位。
    > 解决：调试器配置「暂停时关闭看门狗」。

## 8. 调试工程规范
1. 区分Debug/Release版本：Debug开启调试信息，关闭看门狗；Release关闭多余打印，开启看门狗。
2. 调试代码使用宏包裹，发布时关闭，避免残留调试逻辑。
```c
#ifdef DEBUG
// 调试代码
#endif
```
3. 保留故障码机制：故障发生时记录状态变量，便于复现定位偶现bug。
