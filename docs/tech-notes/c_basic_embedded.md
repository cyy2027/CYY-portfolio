# 嵌入式C语言基础实践笔记
> 📄 文档路径：docs/c_basic_embedded.md
>
> ✍️ 个人实践总结：嵌入式MCU开发C语言核心要点；内存模型、指针、位操作、const/static/volatile关键字、中断安全编码；数组、结构体、对齐、类型强转；项目中常见内存越界、野指针、中断竞态踩坑记录。
## 概述
嵌入式C和PC端C语言侧重点完全不同。MCU资源有限（RAM小、Flash有限），直接操作寄存器、外设，对内存、时序、中断安全要求极高。很多PC上忽略的写法，在嵌入式里会直接造成死机、HardFault。
本文整理嵌入式开发高频C语言知识点，聚焦MCU裸机/FreeRTOS项目编码规范与避坑。

## 一、MCU内存模型
1. **Flash(ROM)**：存放代码、`const`常量，只读，掉电不丢失。
2. **RAM**：全局变量、static局部变量、栈、堆，掉电丢失。
    - 栈stack：函数局部变量、函数调用栈，**空间很小，极易栈溢出**。
    - 全局区：全局变量、static静态变量，程序启动时初始化。
    - 堆heap：malloc动态内存，嵌入式项目尽量少用。
> 嵌入式原则：**大数组不要定义在函数内部（栈上），优先static或者全局**。

## 二、关键字重点解析
1. `const`：变量存放至Flash，节省RAM。
```c
const uint8_t str[] = "hello"; // 存Flash
```
2. `static`
    - 局部static：变量只初始化一次，存全局RAM，跨函数调用保留值。
    - 文件static：函数/变量作用域仅限本.c文件，防止外部引用。
3. `volatile`：**告诉编译器不要优化该变量**。寄存器、中断共享变量必须加volatile。
```c
volatile uint32_t reg_val; // 寄存器读取，禁止编译器缓存优化
```
> 坑：中断和主循环共享的全局变量，缺少volatile会出现读取值异常。

## 三、位操作（寄存器读写必备）
```c
// 置1
REG |= (1 << n);
// 清0
REG &= ~(1 << n);
// 翻转
REG ^= (1 << n);
// 掩码读取
if(REG & (1 << n))
{}
```
> 规范：使用宏定义掩码，不要直接写魔数，便于维护。

## 四、结构体、内存对齐、位域
```c
typedef struct{
    uint8_t a;
    uint32_t b;
}test_t;
```
默认4字节对齐，`a`后面会填充3字节空洞。
- `__attribute__((packed))`：取消对齐，紧凑存储；访问非对齐地址在部分MCU会触发HardFault。
- 位域：节省存储空间，适合寄存器位定义，但可移植性较差。

## 五、指针与函数指针
1. 野指针：指针指向非法地址，直接访问会触发HardFault。使用前判断指针是否为NULL。
```c
if(ptr != NULL)
{
    *ptr = 1;
}
```
2. 函数指针：常用于回调、状态机、Bootloader跳转APP。
```c
typedef void (*func_cb_t)(void);
```

## 六、中断安全编码规则
1. 中断函数**简短**，只做标记，复杂业务交给主循环处理。
2. 主循环与中断共享变量访问需要关中断（临界区保护）。
3. 禁止在中断内部使用`printf`、malloc、延时等耗时函数。
4. 共享标志位使用`volatile`修饰。

## 七、无符号数常见陷阱
```c
uint8_t x = 0;
x--;  // x变成255，不会小于0，容易造成死循环
```
> 循环判断时注意uint类型不能直接判断`i >= 0`。

## 八、工程踩坑记录
1. 函数内部定义超大局部数组，栈溢出直接HardFault。
> 解决：大数组加static，放到全局RAM。
2. 操作寄存器变量不加volatile，编译器优化后读取寄存器值不变。
> 解决：寄存器、中断共享变量增加volatile。
3. 结构体packed压缩后，直接强转指针访问，出现非对齐访问，触发HardFault。
> 解决：谨慎使用packed，避免结构体指针强制转换。
4. 指针不判空，函数传入NULL指针，访问*ptr直接崩溃。
> 解决：所有外部传入指针先判断`ptr != NULL`。
5. 无符号变量做减法判断，逻辑错误。
> 解决：比较边界注意区分有符号/无符号。
6. 中断内执行大量运算、打印串口，中断阻塞丢失事件。
> 解决：中断只置标志位，业务逻辑放到主循环。
