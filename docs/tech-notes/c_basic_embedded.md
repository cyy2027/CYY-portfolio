# 嵌入式C语言开发要点与易错点
> 文档位置：`docs/tech-notes/c_basic_embedded.md`
>
> 说明：本文为嵌入式项目开发总结，聚焦单片机 C 语言工程开发易错点，属于项目实践能力沉淀，**非完整工程源码**，案例来源于 FOC 电机、温控、充电桩项目。

## 1. `volatile` 关键字
作用：阻止编译器优化，每次都从**内存**读取变量，不使用寄存器缓存。

适用场景：
1. 中断服务函数中修改的全局变量
2. 外设寄存器映射地址

```c
// 示例：中断标志，必须加volatile
volatile uint8_t key_int_flag = 0;
```

> 
> 踩坑：不加volatile时，编译器优化后主循环永远读到旧值，程序逻辑卡死。

## 2. `static` / `const` 在单片机中的含义

### `static`

- 函数内局部static变量：存储在**RAM全局区**，不是栈；程序只初始化一次，函数退出后变量保留。
- static函数/全局变量：作用域仅限当前`.c`文件，其他文件不可访问。

> 
> 项目用途：状态机计数、滤波缓存数组，避免放在栈上造成栈溢出。

### `const`

- 全局const常量，一般存放在**Flash**，不占用RAM；适合存放查找表、固定参数。

> 
> 踩坑：不要对const指针指向的内容做写操作，会触发硬件异常。

## 3. 指针、强制类型转换、内存对齐

1. 指针本质是内存地址；单片机开发常用来操作寄存器、解析报文。
2. 结构体强制转换解析数据：注意**内存对齐**
   - 默认按最大成员字节对齐；直接把字节缓冲区强转结构体，容易出现偏移错位，报文解析出错。
   - 解决方案：`__attribute__((packed))` 取消结构体对齐（慎用，部分MCU访问非对齐地址会HardFault）。

```
// 压缩结构体，取消对齐
typedef struct __attribute__((packed))
{
    uint16_t voltage;
    uint16_t current;
} PowerData_t;
```

3. 野指针：使用前判空；不要保存局部变量的地址到全局指针（函数退出后栈内存失效）。

## 4. 位运算（寄存器操作核心）

嵌入式配置寄存器优先使用位掩码，不要直接整体赋值，防止修改其他无关bit。

```
// ✅ 置位bit0
GPIOA->ODR |= (1U << 0);
// ✅ 清零bit0
GPIOA->ODR &= ~(1U << 0);
// ❌ 错误，直接覆盖整个寄存器，会改动其他引脚
GPIOA->ODR = (1U << 0);
```

> 
> 项目场景：FOC项目TIM、ADC寄存器配置大量使用位运算。

## 5. 栈内存风险（高频死机原因）

- 局部变量存放在**栈**，栈空间很小（通常几KB）。
- ❌禁止在函数内部定义大数组：

```
// 危险！大数组放在栈，极易栈溢出HardFault
void func(void)
{
    uint8_t buf[1024];
}
```

✅解决办法：改为`static`局部变量 / 全局变量；嵌入式尽量少用malloc动态内存。

## 6. 宏定义陷阱

宏是文本直接替换，**不是函数**，括号缺失会造成运算优先级错误。

```
// ❌错误
#define MAX(a,b) a > b ? a : b
// ✅正确，全部加括号
#define MAX(a,b) ((a)>(b)?(a):(b))
```

其他注意：宏末尾不要随意加分号；多行宏用`\`换行。

## 7. 中断函数编写规范

1. 中断函数执行时间**尽量短**，只置标志位，业务逻辑交给主循环/任务处理。
2. 禁止在中断内：`printf`、延时函数、复杂浮点运算、大量循环。
3. 共享变量必须加`volatile`；多任务场景可关中断保护。
4. 中断函数不能带参数、不能有返回值。

## 8. 类型与隐式转换坑

1. 无符号数减法：`uint16_t a = 1; a -= 2;` 不会变成负数，会溢出变成很大的正数。
2. 计算尽量保持类型一致，避免隐式转换带来精度丢失。
3. 推荐使用`stdint.h`固定宽度类型：`uint8_t / int16_t / uint32_t`，不同编译器下宽度统一。

```
#include <stdint.h>
```

## 9. 内存分配 malloc / free（嵌入式慎用）

- 碎片化风险：频繁malloc/free造成内存碎片，长时间运行内存耗尽。
- 单片机量产项目，**优先静态内存（全局/静态数组），尽量避开动态内存**。

> 
> 个人项目可以学习使用；产品固件一般禁止频繁malloc。

## 10. 代码规范与工程好习惯

1. 全局变量尽量少用；优先用函数传参、队列传递数据。
2. 魔法数字：用宏定义替代，方便统一修改。
3. 函数单一职责，一个函数只做一件事。
4. 边界判断：数组访问、报文解析，必须判断下标，防止数组越界。
