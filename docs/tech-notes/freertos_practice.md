## 概述
FreeRTOS是Cortex-M平台最常用轻量实时操作系统，提供任务调度、任务间通信机制。很多新手只懂API调用，但容易出现优先级反转、栈溢出、死锁、中断处理不当、资源竞争等隐性bug，在长时间运行后随机死机。
本文整理工程开发规范、内核机制、通信组件选型与实战调试方案，适用于MCU嵌入式项目。

## 一、任务基础
```c
// 任务创建示例
xTaskCreate(task_entry, "task_name", 512, NULL, 2, &task_handle);
```
1. 优先级：数字越大优先级越高。**不要把任务优先级设置全部相同**，关键业务任务设置更高优先级。
2. 栈大小：单位为`word`（4字节，Cortex-M），不是字节。栈预留余量，使用`uxTaskGetStackHighWaterMark`监测剩余栈。
> 工程经验：串口/状态机任务 512word；FOC电机控制任务 1024word；复杂解析任务 1536word。

3. 任务函数必须死循环，**不能return**，return会触发断言崩溃。
```c
void task_entry(void *arg)
{
    while(1)
    {
        //业务代码
    }
}
```

## 二、任务通信组件选型
- **队列 Queue**：异步传递完整数据，FIFO，支持阻塞读写。适合报文、传感器数据转发。
- **二值信号量**：用于**中断通知任务**（事件触发，只标记事件发生）。
- **计数信号量**：多事件累积，脉冲计数场景。
- **互斥锁 Mutex**：保护共享资源（全局变量、外设），自带优先级继承，缓解优先级反转。
> ❗互斥锁**不能在中断中使用**。
- **事件组 EventGroup**：等待多个事件组合，一位代表一个事件。适合多传感器就绪联合触发。

## 三、中断与FreeRTOS规则
1. 中断中只能调用带`FromISR`后缀API：`xSemaphoreGiveFromISR`、`xQueueSendFromISR`。
2. 中断服务函数尽量简短，仅释放信号量/入队，业务交给任务处理。
3. 高优先级中断可以不受RTOS内核屏蔽；内核临界区只屏蔽低优先级中断。
4. `portYIELD_FROM_ISR(xHigherPriorityTaskWoken)`：如果唤醒更高优先级任务，触发任务切换。

## 四、临界区与资源保护
- `taskENTER_CRITICAL()` / `taskEXIT_CRITICAL()`：进入临界区，屏蔽中断。
> 临界区代码必须极短，禁止在临界区内调用延时、队列阻塞函数。
- 共享全局变量、硬件寄存器访问，多任务读写必须加锁。

## 五、典型工程问题
### 5.1 优先级反转
低优先级任务持有互斥锁，高优先级任务等待锁；此时中优先级任务抢占CPU，导致高优先级任务长时间无法运行。
> 解决：使用FreeRTOS Mutex自带**优先级继承**。

### 5.2 死锁
任务A持有锁1等待锁2；任务B持有锁2等待锁1。
> 解决：统一所有锁的获取顺序；锁增加获取超时时间。

## 六、工程踩坑记录
1. 栈空间分配不足，长时间运行栈溢出，随机HardFault。
> 解决：上线前读取栈水位，预留30%余量。
2. 在中断调用普通`xSemaphoreGive()`（非FromISR版本），直接系统崩溃。
> 解决：中断上下文必须使用`xxxFromISR`系列API。
3. 任务内部大量使用printf，阻塞调度，实时性变差。
> 解决：日志放到独立低优先级日志任务，用队列缓存打印。
4. 互斥锁在中断中使用，触发内核断言。
> 解决：中断只使用信号量，Mutex仅限任务内。
5. 长时间阻塞任务不设置超时，任务永久卡死，系统功能失效。
> 解决：所有`xSemaphoreTake`增加等待超时。
6. 多个任务同时操作同一个外设，无锁保护，寄存器状态错乱。
> 解决：外设访问统一加互斥锁。
7. 任务优先级设计不合理，高频率业务任务优先级过低，数据丢失。
> 解决：按实时性划分优先级，控制任务 > 采集任务 > 日志任务。
