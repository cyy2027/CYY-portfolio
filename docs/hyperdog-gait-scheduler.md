> 标识：🔴
> 配套项目：HyperDog 四足机器狗主控固件
> 定位：Trot 对角小跑步态调度工程文档，嵌入式底层实现；不含 MPC，基于固定相位时序 + 五次多项式足端轨迹；Tick 驱动非阻塞调度，输出足端坐标，交给逆运动学求解关节角度。
> 包含：相位划分、五次多项式轨迹、状态机、姿态补偿、相位同步、步态切换、踩坑复盘。
## 1. 模块概述
Trot对角步态是四足最基础、最常用的小跑步态，对角腿（FR & RL、FL & RR）同步运动。
- 调度周期：200Hz（5ms），低于IMU 500Hz、CAN关节下发1kHz，符合算力分配；
- 核心输入：遥控速度指令、躯干姿态（Roll/Pitch）、步态相位标记；
- 核心输出：四条腿足端空间目标坐标，经逆运动学得到关节目标角度，送入CAN发送链路；
- 调度范式：**Tick时间戳驱动，全程无阻塞延时**；相位随时间自动推进，不依赖`HAL_Delay`。

> 边界说明：本模块只做**时序调度+轨迹插值**；步态的平衡优化、质心规划不属于本嵌入式固件实现范围，可后续接入上位机算法。

## 2. Trot步态相位划分
一个步态周期 `T_cycle`，分为**支撑相（Stance）**和**摆动相（Swing）**。
- 支撑相：足端接触地面，腿支撑机体，足端相对地面保持静止；
- 摆动相：足端抬起，向前摆腿，准备下一次落地；
Trot对角配对：
- Group A：FR（前右） + RL（后左）
- Group B：FL（前左） + RR（后右）

相位关系：A组摆动时B组支撑；A组支撑时B组摆动，相位相差半个周期。
相位变量 `phase`：0 ~ 1.0f，随Tick单调递增，超过1.0自动取模回0。
```
phase ∈ [0, 0.5)  → A摆动，B支撑
phase ∈ [0.5, 1.0) → A支撑，B摆动
```

参数定义：
- `gait_period`：步态周期，单位 s；速度越快周期越小；
- `swing_ratio`：摆动相占比，工程常用 0.4（40%摆动，60%支撑）；
- `step_height`：摆腿最大抬腿高度；
- `step_length`：步长，由遥控前后速度指令缩放。

## 3. 足端轨迹：五次多项式插值
选用五次多项式，保证**位置、速度、加速度在起点、终点连续**，落地冲击更小，是嵌入式工程最常用方案。
一维轨迹通用形式：
$$
s(t) = a_0 + a_1 t + a_2 t^2 + a_3 t^3 + a_4 t^4 + a_5 t^5
$$
边界条件：
- t=0：位置=起点，速度=0，加速度=0
- t=T：位置=终点，速度=0，加速度=0

支撑相：足端在机身坐标系匀速反向滑动，抵消机身前进；
摆动相：X方向向前跨步，Z方向抬升-下落，生成弧形摆腿轨迹。

伪代码（摆动相Z向高度轨迹）
```c
// 五次多项式足端高度插值，t∈[0,1]
float Gait_CalcSwingZ(float t, float max_h)
{
    // 五次多项式，0、1端点速度加速度均为0
    float s = 6*t*t*t*t*t - 15*t*t*t*t + 10*t*t*t;
    return max_h * s;
}
```
> 支撑相不使用五次多项式，采用线性匀速插值，降低MCU计算量。

## 4. 非阻塞步态调度主逻辑
基于全局SysTick时间戳推进相位，不阻塞其他任务。
```c
// 步态调度入口，200Hz周期调用
void HyperDog_GaitScheduler(uint32_t tick)
{
    static uint32_t last_tick = 0;
    float dt = (tick - last_tick) * 1e-3f;
    last_tick = tick;

    // 相位累加
    float phase_delta = dt / g_gait_period;
    g_gait_phase += phase_delta;
    if(g_gait_phase > 1.0f)
    {
        g_gait_phase -= 1.0f;
    }

    // 根据相位分组，计算每组足端坐标
    if(g_gait_phase < 0.5f)
    {
        Gait_SwingGroupA(g_gait_phase, g_vel_cmd);
        Gait_StanceGroupB(g_gait_phase, g_vel_cmd);
    }
    else
    {
        Gait_StanceGroupA(g_gait_phase, g_vel_cmd);
        Gait_SwingGroupB(g_gait_phase, g_vel_cmd);
    }

    // 叠加IMU姿态补偿：修正足端坐标，抵抗倾倒
    Gait_AddAttitudeCompensate(&g_leg_pos[0], &g_attitude);

    // 足端坐标 → 逆运动学，输出4条腿关节目标角度
    Leg_IK_Solve(g_leg_pos, g_joint_target_angle);
}
```

## 5. 姿态补偿逻辑（和IMU模块联动）
IMU输出Roll/Pitch躯干倾角，在足端坐标上叠加修正量：
- 机身向前倾（Pitch>0）：前腿抬高、后腿下放，防止栽倒；
- 机身向右侧滚（Roll>0）：右侧腿抬高，左侧腿下放；
> 补偿增益做限幅，不能过大，避免振荡；增益参数存Flash，支持调参。

## 6. 步态平滑切换保护（重点安全逻辑）
禁止步态直接阶跃切换（站立 ↔ Trot），防止冲击摔机：
1. 站立STATE_STAND：四条腿固定在支撑零点，相位冻结；
2. 收到Trot使能指令：先缓慢抬升机体，再解锁相位，逐步放大步长；
3. 收到停止指令：先逐步缩小步长到0，相位冻结，回归站立姿态；
4. 切换过程设置过渡时间（0.3~0.5s），步长做一阶低通滤波。

> 步态切换受控于整机状态机（hyperdog_arch.md），只有在STATE_STAND状态才允许切入Trot。

## 7. 输入限幅与指令保护
遥控速度指令直接决定步长，必须做保护：
- 速度死区：摇杆微小抖动不产生步长；
- 一阶低通滤波：速度突变被平滑；
- 最大步长硬限幅，防止步长过大导致机械干涉；
- 故障标志置位时，直接锁死步态，停止相位推进，进入安全收腿。

## 8. 实测踩坑记录（面试高频）
1. 相位失步：四个腿更新时序不一致，对角腿相位错位，机身横摆、抖动；
   解决：统一在同一个调度周期内一次性计算四条腿目标，再批量下发CAN；
2. 落地冲击大：摆动相轨迹末端加速度不为0；
   解决：必须五次多项式，不要用简单梯形速度曲线；
3. 姿态补偿正反馈：补偿增益太大，机身一倾斜就越补越歪，直接翻倒；
   解决：增益从小慢慢上调，增加低通，设置补偿上限；
4. 步态频率和结构共振：步态周期和机架共振频率重合，整机剧烈抖动；
   解决：预留步态周期参数，调试时避开共振点；
5. 指令跳变：遥控丢包恢复瞬间速度突刺，步长瞬间拉满；
   解决：速度指令FIFO+平滑滤波；故障时直接清零步长；
6. 浮点耗时：大量三角函数、高次多项式导致200Hz任务超时；
   解决：开启FPU，精简计算，支撑相改用线性插值。
