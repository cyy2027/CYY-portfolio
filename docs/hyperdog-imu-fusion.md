# HyperDog四足机器狗：IMU姿态融合与电机振动抑制
📄 文档路径：docs/hyperdog-imu-fusion.md
> 
> 标识：🔴
> 配套项目：HyperDog 四足机器狗主控固件
> 定位：IMU 姿态融合工程文档，面向嵌入式底层；重点解决足式机器人特有电机振动污染问题，实现稳定四元数姿态输出，用于姿态补偿。
> 包含：采样方案、互补滤波原理、振动抑制策略、姿态漂移补偿、时序对齐、踩坑复盘。

## 1. 模块概述
主控板搭载 ICM20602（6轴IMU：加速度计+陀螺仪），I2C+DMA方式采集原始数据，采样频率500Hz。
- 输出：四元数、俯仰角Pitch、横滚角Roll（航向Yaw不做强约束，四足不依赖航向闭环）
- 用途：躯干姿态反馈，步态调度器做姿态补偿；姿态超限触发倾倒保护
- 核心难点：机器狗电机PWM、减速器、足端落地冲击带来高频振动，直接污染陀螺仪，普通互补滤波极易漂移、姿态抖动。
> 边界说明：本方案不使用EKF，优先选用**计算量小、适合MCU实时跑的互补滤波**，主控算力留给CAN和步态调度。

## 2. 硬件与时序设计
1. 通信：I2C，DMA循环采集，避免轮询阻塞；
2. 采样频率：500Hz，和IMU采样寄存器ODR对齐；
3. 量程配置：
    - 陀螺仪 ±2000 dps（行走姿态变化快，大量程）
    - 加速度计 ±16 g（落地冲击加速度很大）
4. 采样对齐：IMU采样时间戳打上SysTick，和CAN下发、步态调度时序对齐；
5. 电源：IMU独立LDO，远离电机功率回路，减少电源耦合噪声。

> 时序约束：IMU采样、滤波、姿态输出任务500Hz稳定运行，抖动控制在200us以内。

## 3. 原始数据预处理
原始数据拿到后先做预处理，再送入融合：
1. 零偏校准：上电静置3s采集陀螺仪零偏，求取均值补偿；加速度计静态校准，修正重力偏移；
2. 滑动限幅滤波：区分**重力加速度**和**冲击振动加速度**；
3. 振动标志位判定：加速度模值偏离1g过大，判定为落地冲击/强振动阶段，此时降低加速度计权重；
4. 单位转换：陀螺仪原始LSB → rad/s；加速度原始LSB → m/s²。

伪代码：
```c
// IMU零偏补偿
void IMU_OffsetCompensate(ImuRaw_t *raw, ImuOffset_t *offset)
{
    raw->gx -= offset->gx_bias;
    raw->gy -= offset->gy_bias;
    raw->gz -= offset->gz_bias;
}

// 振动检测：加速度模偏离1g过多，判定冲击
bool IMU_IsShock(float ax, float ay, float az)
{
    float norm = sqrtf(ax*ax + ay*ay + az*az);
    if(fabsf(norm - 9.8f) > 4.0f)
    {
        return true;
    }
    return false;
}
```

## 4. 互补滤波融合逻辑
四元数版本互补滤波，避免欧拉角万向锁问题。
- 陀螺仪：高频、动态响应好，长期会漂移；
- 加速度计：低频，静态重力方向准，动态冲击下不可信；
- 融合思路：**动态振动大时，信任陀螺仪；静态/平稳站立时，提高加速度计权重修正漂移**。

滤波参数自适应：
- 平稳状态：α=0.98（陀螺仪权重0.98，加速度0.02）
- 冲击/振动状态：α=0.995（几乎只信任陀螺仪，加速度权重压低）

融合流程：
1. 陀螺仪积分更新四元数；
2. 利用加速度计重力向量，计算误差向量；
3. 误差向量PI校正陀螺仪；
4. 归一化四元数，防止数值发散；
5. 四元数转欧拉角Pitch/Roll输出给上层步态模块。

> 不做Yaw角修正：加速度无法观测航向，Yaw会缓慢漂移，符合四足机器人设计习惯，航向由遥控控制。

## 5. 四足专属：振动与落地冲击抑制策略（面试重点）
普通平衡小车、飞控IMU方案不能直接照搬，四足特有优化：
1. **自适应权重互补滤波**：支撑相、摆动相、落地冲击阶段切换滤波系数；步态调度器输出相位信号给IMU模块，提前预知即将落地，提前压低加速度权重；
2. 中值滤波+滑动窗口：对陀螺仪原始数据做短窗口中值滤波，剔除尖峰脉冲噪声；
3. 姿态输出低通：给最终欧拉角增加一阶低通，滤除残余高频抖动；截止频率不能太低，否则姿态反馈滞后，导致步态摔倒；
4. 异常值锁存：连续多次检测到超大冲击，暂时冻结姿态修正，等冲击结束后恢复；
5. 机械层面：IMU采用橡胶减震垫，远离电机本体，减少结构振动传递。

## 6. 姿态输出与上层接口
对外输出结构体：
```c
typedef struct
{
    float q0, q1, q2, q3;      // 四元数
    float roll;    // 横滚 rad
    float pitch;   // 俯仰 rad
    float yaw;     // 航向 rad（不做修正，仅供观测）
    uint8_t shock_flag;        // 冲击标记 0=平稳 1=强振动
    uint32_t tick;              // 时间戳，和步态时序对齐
}Attitude_t;
```
数据通过队列传给步态调度任务，避免全局变量竞争。

## 7. 故障判定
- 陀螺仪数据卡死不变：判定IMU通信丢失，上报故障；
- 姿态Pitch/Roll超过±30°：判定倾倒风险，触发整机保护（hyperdog-safety.md）；
- 连续长时间无法收敛：判定滤波发散，告警。

## 8. 实测踩坑记录
1. 上电直接漂移：零偏采集时机不对，上电时机器狗晃动，零偏采样不准；必须强制静置3s，不满足静止条件则拒绝完成校准；
2. 小跑时姿态疯狂抖动：加速度计在落地冲击阶段还参与融合，冲击向量污染重力方向；解决方案：自适应降低加速度权重；
3. 滤波滞后：一味加大滤波，姿态反馈滞后，步态补偿跟不上，容易侧翻；需要在抖动和滞后之间权衡；
4. DMA丢采样：I2C DMA缓冲区溢出，采样跳变；增加DMA半完成中断，双缓冲乒乓采集；
5. 时间戳不对齐：IMU采样和步态不同步，补偿时机错乱；所有模块统一基于SysTick时间戳；
6. 四元数不归一化：长时间运行四元数模值发散，姿态慢慢飘飞，每次融合后必须归一化。
